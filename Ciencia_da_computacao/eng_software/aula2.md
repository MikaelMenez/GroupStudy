# Definição 
Área do conhecimento relacionado as todos os aspectos da produção de software, desde os estágios iniciais da especificação do sistema até sua manutenção durante o uso

# Investimentos
- é mais caro manter do que desenvolver software
- representa uma fração significativa do PIB de países desenvolvidos 
- o desenvolvimento de software deve ser custo-efetivo
- software costuma custar mais que hardware 

# Falhas 
resultado da complexidade crescente dos sistemas

## Complexidade crescente dos sistemas
**Demandas mudam à medida que técnicas de engenharia de software nos ajudam a construir sistemas maiores e complexos** 

- precisam ser construídos e entregues mais rapidamente
- geram demanda de sistemas maiores e ainda mais complexos
- incorporam novos recursos, antes considerados impossíveis 

## Falta de adoção de métodos de engenharia de software
**É fácil escrever sistemas de software sem engenharia de software**

- Não usam métodos e técnicas de engenharia de software no dia a dia
- costumam ser mais caros, menos confiáveis e entregues com atraso

# Profissional X amador

## Profissional
Costuma ocorrer em equipes.
Inclui processos, métodos e técnicas que apoiam a especificação, projeto e evolução do sistema de software.
O sistema é desenvolvido para uso e evolução de terceiros.
Deve incluir documentação da especificação, projeto, implementação e uso do sistema

## Amador
É basicamente uma atividade de programação primariamente individual.
O programa é escrito para uso próprio e raramente evolui.
Não requer documentação detalhada

# Software 
**É todo o conjunto de programa de computador, a documentação , bibliotecas, site de apoio, etc.** 
pode ser desenvolvido para um cliente em especifico ou para o mercado em geral 

## Atributos de um bom software
- Prover a funcionalidade e o desempenho requerido pelo cliente
- Deve ser de fácil manutenção, usável e com dependabilidade (engloba vários aspectos, como confiabilidade, disponibilidade, segurança, integridade, resiliência)

# Atividades e Desafios

## Atividades 
- Especificação de software
- desenvolvimento de software (projeto e implementação)
- Validação de software
- evolução de software

## Desafios 
- Lidar com a crescente diversidade de métodos e ferramentas
- Gerenciar demandas por menores prazos de entrega 
- Desenvolver sistemas de software confiáveis

# Custos e técnicas

## Custos
- 60% do custo é voltado ao desenvolvimento, enquanto 40% é voltado aos testes 
- evolução frequentemente supera os custos de desenvolvimento

## Técnicas 
- diferentes técnicas são adequados para diferentes tipos de sistemas
  - jogos devem ser desenvolvidos usando uma série de protótipos
  - sistemas críticos requerem especificações completas e analisáveis
- não há métodos ou técnicas que sejam bons para todos os casos 

# Tipos de produtos 

## Produto genérico
- sistema é vendido no mercado para qualquer cliente
- Organização desenvolvedora controla a especificação e evolução do produto 

## Produto personalizado
- sistema é encomendado e desenvolvido para um cliente em particular
- Organização desenvolvedora projeta e desenvolve o sistema especificamente para o cliente contratante
- cliente contratante controla a especificação e evolução do produto
- Também denominado produtos ***produto sob medida***

## Produto configurável
- sistema construído tendo por base um produto genérico, que é então customizado/adaptado para atender às necessidades de um cliente
- sistema grande e complexo é adaptado para cada cliente
  - incorpora informações sobre regras e processos de negócio, relatórios necessários, etc.
- Organização desenvolvedora controla a especificação e evolução do produto com base necessidades dos potenciais clientes 

**Distinção entre produto genérico e personalizado está se tornando cada vez mais cabulosa** 

# Qualidade de software
- não está relacionada apenas às funcionalidades do software
- deve incluir:
  - comportamento do software em execução
  - estrutura e organização dos programas do sistema
  - documentação associada
- Reflete nos chamados atributos não funcionais
  - tempo de resposta a consultas do usuário 
  - inteligibilidade do código do programa 

**Produtos de software são usados e alterados por terceiros** 

## Atributos essenciais da Qualidade

### Mantunebilidade 
- deve ser escrito de forma que possa evoluir para atender às necessidades mutáveis dos clientes
- É um atributo crítico uma vez que mudanças de software representam um requisito inevtável do software

### Dependabilidade 
### Eficiência 
- Não deve desperdiçar recursos do sistema
- Inclui responsividade, tempo de processamento , uso de recursos

### Aceitabilidade 
- Deve ser considerado aceitável por seus usuários típicos
- Implica em ser inteligível, útil, e compatível com outros sistemas adotados por seus usuários típicos

# Importância da engenharia de software
- numa sociedade dependente de software, a engenharia é a responsável por diminuir os custos, aumentar a mantunebilidade e garantir o prazo
